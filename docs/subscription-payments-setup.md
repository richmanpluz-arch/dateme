# DateMe subscription payments setup

Payment code is on `feature/subscription-portals-navigation`. It is not enabled in production. Do not merge the branch or deploy the Supabase migrations/functions to the production project without explicit release approval.

## Plan pricing

The migration creates five disabled plan rows in `public.subscription_plan_prices`. No prices are assumed. After the migration is applied to the intended environment, sign in with an administrator account and open **Admin portal → Subscription pricing**. Set both:
- OneVoucher price in ZAR
- Crypto price in USD

Enable a plan only after both values are correct. Keep it disabled while deciding prices.

## Required Edge Function secrets

Configure these in Supabase Dashboard → Edge Functions → Secrets for the target environment. Never commit or send secret values in chat.

- `NOWPAYMENTS_API_KEY` — NOWPayments API key.
- `NOWPAYMENTS_IPN_SECRET` — NOWPayments IPN secret generated in Store/Payment Settings.
- `KORA_SECRET_KEY` — Kora secret key for the merchant account with South African 1Voucher payments enabled.
- `KORA_1VOUCHER_PROVIDER_CODE` — provider code confirmed by Kora; default in code is `0001`, verify with your account before live use.
- `APP_URL` — full public app URL for successful/cancelled crypto invoice returns, with no trailing slash.
- `APP_ORIGIN` — exact app origin used for CORS, e.g. the relevant Vercel deployment origin.

Supabase supplies its standard `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` runtime variables. Never expose the service role key to the browser.

## Deployment order (test environment first)

1. Apply `supabase/migrations/20261024100000_subscription_payments.sql`.
2. Apply `supabase/migrations/20261024101500_admin_subscription_payments.sql`.
3. Deploy `subscription-pricing` with JWT verification disabled because it returns only published plan prices.
4. Deploy `create-subscription-payment` with JWT verification enabled.
5. Deploy `payment-webhook` with JWT verification disabled; it authenticates provider callbacks using provider signatures.
6. Add the secrets above, configure the provider webhook/IPN URL as `<SUPABASE_URL>/functions/v1/payment-webhook?provider=nowpayments` in NOWPayments, and use the Kora notification URL generated by checkout for OneVoucher.
7. Test successful, failed, cancelled, duplicate and mismatched-amount notifications in sandbox/test mode before enabling any plan for real members.

## Important

- NOWPayments requires a valid API key and IPN secret. Its webhook is verified with HMAC-SHA512.
- Kora must approve/enable 1Voucher for the merchant account. Its webhook is verified with the Kora signature and HMAC-SHA256.
- A browser redirect is never treated as payment proof.
- OneVoucher PINs are sent to Kora for processing and are not stored in DateMe's payment-order table.
- Do not enable real prices until the provider accounts, webhook signatures, return URL and payment lifecycle have been tested end to end.
